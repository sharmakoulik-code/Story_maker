# Phase 3 verification — 2026-11-18

Koma Studio 0.3.0, tested on the Linux sandbox with two logical CPU threads, about 3.8 GiB RAM, and no detected GPU. The storyboard imports images and tracks reviews; it does not run image inference. The demo shows the difference between an approved still and an imported replacement that still needs review.

## Blue-flower visual acceptance

The browser test started with an empty, private library. It created a Character Library design, imported a reference, entered the [exact blue-flower story](../tests/fixtures/blue_flower.txt) with a 30-second target, and applied the saved design to the main character without changing her scene links. It approved the three-scene plan, imported one original illustration per scene, and checked that the 360 × 640 thumbnails decoded. The illustrations were drawn for the demo, not generated by a model. See the [artwork source and license](../backend/demo_art/README.md).

| Operation | Result |
|---|---|
| Approve one scene, then approve a selection of two | All three imported 540 × 960 stills were approved. |
| Replace the old-tree frame | Only scene 2 went back to **Needs review**. Scenes 1 and 3 kept the same image IDs and approval records. A companion API test confirmed that the earlier scene 2 file was still readable and byte-for-byte unchanged. |
| Force-stop the backend after the save, then relaunch | Version history, the active selection, approved frames, and the library reference survived. Reselecting the earlier tree frame required a new approval. |
| Edit the camera direction and reorder scenes | The frames followed their scene IDs, not their positions. Only the edited shot needed visual re-review. Adding/removing a scene was also exercised in the board. |
| Change the library’s active reference | The project retained the pinned earlier reference. Separate API tests reused the same design in two projects and verified both pins survived a replacement and an archive. |

Both the storyboard and Character Library layout passed the 390 px width check. Desktop and mobile views of the seeded sample were also inspected in Chromium. This acceptance is for **locally imported illustrations**, not generated or animated shots.

## Test results and safeguards

- **40 Python tests, three Chromium workflows, and the production build passed.** This includes v1/v2/v3 database fixtures upgrading to SQLite schema 4, preservation of plan snapshots, stale/archived write guards, review conflicts, all-or-nothing batch approval, image-ownership checks, and reopening old plans with their original shot IDs. Renamed/reordered scenes stay attached to their artwork; replanning gives new scene IDs and keeps old media off the board.
- **Still imports:** decoded PNG, JPEG and WebP; rejected invalid, animated, over-pixel-limit and over-byte-limit input. Verified orientation correction, removal of source camera metadata, and bounded thumbnail size. Imports are written to managed local folders with generated filenames; a failed database activation rolled back and left the previous version intact. A process death during an import can leave unreferenced files on disk, but they are not activated or used by the storyboard. Rendering-job recovery is not part of this test.
- **Offline checks:** the browser blocked every request outside the app’s loopback origin and recorded zero outside-origin attempts. A Python socket guard recorded no TCP connection attempts during import, file reads, or frame approval. This was not a physical disconnect test. Optional runtime diagnostics still probe loopback as before.
- **CPU timing, not inference:** ten normalization runs per input took a median of about **0.29 s** for the 540 × 960 demo still and **0.52 s** for a 720 × 1280 resized illustration, including writing and flushing the full copy and thumbnail. Times exclude HTTP, SQLite, and browser work. Larger or noisier sources can take much longer and lossless copies can grow in size. Start with 540 × 960 or 720 × 1280 artwork on low-resource devices.
- **Windows packaging:** the Python 3.11 x64 runtime requirements resolved to Windows-compatible wheels, including Pillow. The batch launchers and native Windows image codecs have not been run on a Windows PC.

## Repeat the tests

See the [test setup and commands](phase-1-verification.md#repeat-the-tests). `setup.bat` installs [Pillow 13.0.0](https://github.com/python-pillow/Pillow) (MIT-CMU) for local decoding, orientation, thumbnails and encoding, and [python-multipart 0.0.34](https://github.com/Kludex/python-multipart) (Apache-2.0) for the local file picker requests. These packages are downloaded only during explicit setup. The browser driver is test-only. Neither a media engine nor model weights are downloaded.
